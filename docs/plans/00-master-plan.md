## 四、多模型配置 — 混合模式 + 双预设一键切换

### 4.1 核心设计

采用 **PlotPilot 式手动绑定**（非自动路由），扩展为按阶段配置：

```
┌─────────────────────────────────────────────┐
│  设置页 → 模型配置                            │
│                                              │
│  当前预设: [🔥 实用版 ▾]  [切换到: 旗舰版]     │
│                                              │
│  全局默认模型: [claude-opus-4-7-medium ▾]      │
│  ──────────────────────────────────           │
│  阶段覆盖 (不填则用全局默认):                   │
│  ├─ 章节正文:  [claude-opus-4-7-medium ▾]     │
│  ├─ 大纲规划:  [gemini-3.1-pro-high ▾]       │
│  ├─ 章后管线:  [gemini-2.5-flash ▾]          │
│  ├─ 拆书提取:  [gemini-2.5-flash ▾]          │
│  ├─ 拆书深度:  [gemini-3.1-pro-high ▾]       │
│  ├─ 文风检测:  [claude-opus-4-7-medium ▾]     │
│  ├─ 审核校对:  [gemini-3.1-pro-high ▾]       │
│  ├─ 学习Agent: [gemini-2.5-flash ▾]          │
│  ├─ 提示词优化: [claude-opus-4-7-medium ▾]    │
│  ├─ 数据预测:  [gemini-3.1-pro-high ▾]       │
│  └─ 向量嵌入:  [text-embedding-3-small ▾]     │
└─────────────────────────────────────────────┘
```

**零自动判断**：每个阶段用什么模型，由用户在设置页手动选定，运行时固定读取，不做任何智能切换。

### 4.2 双预设方案 — 一键切换

### 4.3 实现方式

```python
# 运行时读取配置，完全确定性，无自动判断
class StageModelResolver:
    STAGES = [
        "chapter_writing", "outline_planning", "post_chapter_pipeline",
        "book_analysis_extract", "book_analysis_deep", "style_detection",
        "audit_review", "learning_agent", "prompt_optimization",
        "prediction", "embedding"
    ]

    def get_profile_for_stage(self, stage: str) -> LLMProfile:
        # 1. 查当前预设中该阶段的绑定
        override = self._get_stage_override(stage)
        if override:
            return override
        # 2. 没有覆盖 → 返回全局默认
        return self._get_global_default()
```

### 4.4 UI 交互

- 设置页顶部: **预设切换器** `[🔥 实用版] [👑 旗舰版] [自定义]`
- 点击预设一键填充所有阶段绑定
- 切换后可单独修改某个阶段（自动变为"自定义"）
- 每个阶段下拉框只显示已配置的 LLM Profile（和 PlotPilot 控制面板一致）
- 运行时在写作界面顶部显示当前章节使用的模型名，让用户随时知道在用什么

## 五、⑤ 发布引擎 (全新)

基于 PlotPilot-new 已有的 Playwright 番茄/起点发布器扩展。

### 5.1 自动发布

| 功能 | 说明 |
|------|------|
| **番茄小说发布** | Playwright自动化: 登录态管理→选书→粘贴章节→设置定时→提交 |
| **起点中文网发布** | 同上, 适配起点作家后台 |
| **定时发布** | 设置发布计划: 每天几点发几章, 自动队列执行 |
| **多平台同步** | 一章写好→同时发布到番茄+起点(可配置延迟) |
| **发布前审核** | 自动检查: 敏感词/违禁内容/字数要求/格式规范 |
| **发布状态追踪** | 记录每章发布时间/状态/平台, 失败自动重试 |

### 5.2 数据采集

| 数据维度 | 采集方式 | 频率 |
|---------|---------|------|
| **作品总览** | 阅读量/收藏/推荐票/月票 | 每日 |
| **章节数据** | 每章阅读量/评论数/追更率 | 每日 |
| **追更留存** | 读到第N章的人数占比 (漏斗) | 每周 |
| **评论分析** | 读者评论情感/关键词/诉求 | 实时 |
| **排行榜** | 所在分类排名变化趋势 | 每日 |
| **收入数据** | 稿费/打赏/签约状态 | 每周 |

### 5.3 数据看板 (前端)

- 阅读量/收藏/追更 折线图 (按天/周/月)
- 章节漏斗图: 读者在哪一章流失
- 读者情感词云: 从评论提取
- 竞品对比: 同分类热门书的数据对比
- 发布日历: 发布计划+实际执行+数据反馈

## 六、⑥ 数据预测引擎 (全新)

### 6.1 预测模型

基于实际采集的数据训练预测能力：

| 预测目标 | 输入特征 | 方法 |
|---------|---------|------|
| **阅读量预测** | 题材/标签/简介/前3章文风/标题 | LLM + 历史数据回归 |
| **追更率预测** | 章节张力曲线/伏笔密度/爽点分布 | 基于漏斗数据学习 |
| **签约概率** | 题材热度/前N章质量评分/字数 | 分类模型 |
| **收入预测** | 当前数据趋势/同类书表现 | 时序预测 |
| **最佳发布时间** | 历史各时段阅读量分布 | 统计分析 |

### 6.2 实现路径

1. **冷启动**: 用 LLM 基于题材/简介/前3章做粗略预测 (无需历史数据)
2. **数据积累**: 采集自己和热门书的数据, 建立基准线
3. **模型训练**: 数据足够后, 训练轻量回归/分类模型
4. **持续优化**: 每次发布后用实际数据修正预测

### 6.3 写作前预评估

开始写小说前, 输入题材+简介+前3章, 系统给出:
- 🔮 预测阅读量区间 (基于同类书历史数据)
- 📊 题材热度指数 (当前市场数据)
- ⚠️ 风险提示 (题材饱和度/竞争强度)
- 💡 优化建议 (标题/简介/标签调整)

定期基于学习成果优化系统：

| 优化目标 | 方法 | 频率 |
|---------|------|------|

## 九、拆书功能详细设计

### 9.1 管线

```
导入(.txt/.epub/.docx) → 智能切分 → 实体预扫描(jieba+LLM)
    → 逐章深度提取(人物/事件/关系) → 全局聚合
    → 输出: 逆向大纲 / 人物图谱 / 时间线 / 伏笔网 / 文风指纹 / 百科
```

### 9.2 拆书→创作衔接

- **仿写**: 文风指纹→声线锚点Prompt→新作匹配风格
- **续写**: 断点续写, 自动加载人物状态/伏笔/大纲
- **改写**: 选章→基于原设定重写
- **学习**: 拆书结果→知识库→创作时上下文注入

## 十三、关键技术决策

| 决策点 | 选择 | 理由 |
|--------|------|------|
| 图谱存储 | 内存图+JSON | 降低部署门槛 |
| 向量库 | ChromaDB嵌入式 | 零配置 |
| 编辑器 | Tiptap (ProseMirror) | Vue生态最优 |
| 可视化 | D3.js + ECharts | D3做图谱, ECharts做统计 |
| 爬虫/发布 | Playwright | 已有番茄/起点代码可迁移 |
| 定时调度 | APScheduler | 轻量, 不需要额外依赖 |
| 预测模型 | LLM冷启动→轻量ML | 先用后有数据再训练 |
| 多模型配置 | 混合模式+双预设 | 手动绑定+全局兜底, 零自动判断 |
