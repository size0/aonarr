## 二、架构设计对比

### 2.1 oh-story-claudecode：技能管道架构

核心思路：将小说创作拆成独立 Skill（扫榜-拆文-写作-去AI味），每个 Skill 内分 Phase 流水线。

**9个 Skill**：story-long-scan / story-long-analyze / story-long-write / story-short-scan/analyze/write / story-deslop / story-cover / browser-cdp

**关键设计**：
- 按需加载 references：每个 SKILL.md 声明入口，12+ 篇 reference 按需延迟加载
- 项目文件结构化：强制 `设定/角色/` `大纲/细纲_第XXX章.md` `正文/` `追踪/伏笔.md`
- 对标系统：`对标/` 目录存放竞品原文 + 拆文报告，写作时引用同位置章节
- Skill 间流转：明确的流水线位置标注和跳转命令

**story-long-write 参考知识体系（12个 reference 文件）**：
- `outline-arrangement.md` — 大纲排布方法论（2590行，含五步大纲法、矛盾设计、升级感设计等 20+ 方法论）
- `hook-techniques.md` — 钩子技法（862行，章尾13式+章首7式+段落级钩子）
- `anti-ai-writing.md` — 去AI味全流程（394行，三遍去AI法+改写范例）
- `opening-design.md` / `character-design.md` / `genre-frameworks-unified.md` / `style-modules.md` / `dialogue-mastery.md` / `emotional-arc-design.md` / `reversal-toolkit.md` / `quality-checklist.md` / `narrative-units.md`

### 2.2 Lorn.NovelWriteSkills：工程化分层架构

核心思路：小说写作视为工程化生产线，按「通用能力本体 - 题材包装层 - Prompt 入口」三层分离。

**分层模型**：`用户任务 -> 题材Prompt(入口) -> 题材Skill(路由+边界) -> 通用Skill(能力本体)`

**通用 Skill 体系（50+个，分5大模块）**：

| 模块 | 数量 | 代表性 Skill |
|------|------|-------------|
| 构思与设计 | 8 | 设计题材定位/故事面/人物传记/总大纲/事件案件引擎/线索伏笔台账 |
| 写作执行 | 10 | 创建小说正文/章节创作闭环/生成章节控制卡/执行场景单元/执行对话冲突/强化章首章末 |
| 修订与质控 | 9 | 正文润色/去AI味重写/审阅大纲-人物-设定-章节/大纲审阅优化闭环 |
| 商业化与分发 | 9 | 提纯母稿/多平台适配/输出编排/设计书名-简介-封面/平台签约评估/竞对分析/组包投稿 |
| 多平台输出 | 13 | 番茄/七猫/知乎/豆瓣/出版社/微信/百家号/小红书/B站/微博/MyFiction/GoodNovel/WebNovel |

**独特设计**：
- **5段4门禁流程**：探索段-架构段-建模段-生产段-发行段，门禁G1-G4逐段把关
- **两段式建模**：总纲前轻量底盘（核心欲望+关键短板+主要关系冲突），总纲后重度定稿
- **裁判源复核机制**：每个 Skill 强制要求先读人物传记+技术设定再动手，不允许凭印象创作
- **去AI味三档手术强度**：皮相拆洗(层级1) / 骨肉重塑(层级2) / 灵魂重构(层级3)，必须先定档再改
- **四维病灶诊断**：习惯用语、句式逻辑、写法口气、论证逻辑，45条规则总表
- **脚本门禁**：`count-chapter.ps1` 正文字数(3500-6500 CJK)、`count-afterword.ps1` 作者有话说(200-300 CJK)、`scan_text_quality.ps1` 文本质量扫描、`run_quality_gate.ps1` 质量门禁
- **章节创作闭环**：9.2+终审门槛（连续两轮独立终审均>9.2才放行），带日志续跑和断点恢复
- **运营回流**：分发数据反哺创作（读者反馈->下一卷大纲/控制卡/人物关系策略）

### 2.3 long-novel-writer：状态机驱动架构

核心思路：基于 AI_NovelGenerator 项目的提示词蒸馏，用文件系统驱动的状态机管理百万字小说。

**5阶段工作流**：
1. 作品初始化 — 读取/创建作品目录，按 file-contract.md 规范
2. 百万字架构 — 整书主线-卷-篇章单元-chunk(3-5章)-单章，多层循环
3. 章节生成 — 确认上下文后按提示词工作流生成
4. 记忆更新 — 每章更新摘要/角色/伏笔/世界观，每3-5章更新chunk摘要，每卷沉淀
5. 一致性审校 — 设定冲突/角色OOC/伏笔遗漏/节奏断裂/重复桥段

**必备记忆层（8个文件）**：metadata.md / story-bible.md / volumes.md / characters.md / worldbook.md / foreshadowing-ledger.md / summaries.md / continuity-issues.md

**提示词体系（双分支）**：
- 旧分支中文提示词：16个提示词覆盖完整写作链路（角色/世界观/剧情架构/章节正文/摘要/知识库/一致性）
- dev分支提示词：12个提示词覆盖从一句创意到结构化小说

**独特设计**：
- 文件即状态：「作品状态以文件为准，不以当前对话记忆为准」
- 检索/RAG规则：进入百万字规模时默认需要检索层，检索前生成3-5组关键词
- 检索结果分类：情节燃料/人物维度/世界碎片/叙事技法/冲突预警

### 2.4 inovel：桌面 IDE 架构

核心思路：为小说创作构建类 IDE 体验，Tauri 2 跨平台桌面应用。

**技术栈**：Vue 3 + TypeScript + Naive UI + Tailwind CSS + Tiptap 3(编辑器) + Rust(Tauri 2) + SQLite + Git

**60+ Tauri 命令**覆盖：项目管理 / 章节管理 / 世界观管理 / 写作工具 / 模板管理 / 灵感板 / 导出 / 版本控制 / 备份 / 配置

**核心特性**：
- 富文本编辑器（Tiptap 3）
- 世界观管理系统（角色/地点/组织/物品，关系图谱）
- 时间线管理
- Git版本快照（自动提交/手动提交/差异对比/回滚）
- 数据备份与恢复
- 敏感词检测
- 灵感板（图片/文字/链接混合看板）

### 2.5 novel-hub：File-as-Truth 架构

核心思路：Markdown 文件为真相源，SQLite 仅存索引/统计/搜索数据。

**核心原则**：
- File-as-Truth, DB-as-Index
- 编辑冲突检测 + 原子写入
- 功能开关控制高级模块（AI/图谱/时间线/场景/线索）
- API Key 加密存储
- 移动端只读视图（小屏自动降级）

### 2.6 AINovel：批量生成架构

核心思路：面向效率的AI小说批量生成器。

**技术栈**：.NET 8 + WPF + HandyControl + CommunityToolkit.Mvvm + SqlSugarCore + SQLite

**核心特性**：
- 多账户管理（多API Key轮换）
- 提示词管理（公共+私有）
- 文件上传+核心情节点拆分（Markdown/Word）
- OpenAI兼容API流式输出
- 批处理+并发控制（System.Threading.Channels）

## 三、去AI味（Anti-AI-Detect）能力对比

这是所有项目中最关键的差异化能力之一。

### 3.1 oh-story 的去AI味体系

**story-deslop Skill（3阶段）**：
1. AI味扫描 — 逐段检测禁用词和句式
2. 诊断分级 — 按严重程度排序
3. 逐项清除 — 6个门：禁用词替换/句式调整/心理描写外化/节奏打散/对话去腔/结尾去升华

**banned-words.md 分两级**：
- 一级（必须替换）：嘴角微微上扬/眼眸/不禁/竟然/缓缓/淡淡/微微...
- 二级（高频时替换）：情绪/氛围/意味深长/若有所思...
- 禁用句式：「XX的同时，XX」/「不仅XX，更XX」/「仿佛XX一般」...

**anti-ai-writing.md 核心规则**：
- 段落不超过3句话
- 动作+对话+情绪反应的组合写法
- 短句为主
- 口语化/生活化
- 连续12字不得重复原文（连续复用禁令）
- 三遍去AI法：Strip Generic → Cut Professional Diction → Restore Human Presence

## 六、核心方法论提炼

### 6.1 长篇结构设计

**oh-story 方法论栈**（来自 outline-arrangement.md，2590行）：
- 五步大纲创建法：确定高潮→确定单元剧→故事线组织与信息点预埋→确定开篇舞台→确定收尾
- 故事结构分级 / 升级感三步设计法 / 节点设计法 / 主线支线设计法
- 矛盾四重递进 / 三大驱动力反推剧情法 / 设定推演剧情法
- 双线结构法 / AB交织法 / 情绪拉扯=打牌 / 噱头-主线-核心爽点框架
- 金手指设计五问 / 冲突设计要点 / 信息传达顺序体系

**long-novel-writer 核心机制**（来自 long-serial-method.md）：
- 多层循环：整书主线→卷主线→篇章单元(10-30章)→Chunk(3-5章)→单章
- 节奏规则：每3-5章小闭环，每10-30章篇章目标，每卷回收+打开
- 一致性规则：写前检查6项（角色认知/动机/世界规则/道具连续/冲突推进/桥段重复）
- 写后更新4个文件（summaries/worldbook/characters/foreshadowing-ledger/continuity-issues）
- 爽点交替8种：身份落差/信息差/规则利用/反杀/关系变化/资源夺取/真相揭露/代价承担

**Lorn 流程框架**：
- 5段4门禁（探索-架构-建模-生产-发行）
- 两段式建模（总纲前轻量/总纲后重度）
- 章级节拍护栏：钩子→冲突→中段回报→新风险
- 每3-5章形成小单元闭环
- 运营回流：分发数据→下一卷大纲

### 6.2 去AI味核心原则（三项目共识）

1. **具象化原则**：用动作/感官/物件/口头反应替代抽象情绪总结
2. **节奏打散**：破均匀句群，恢复呼吸点
3. **对话个性化**：重要人物必须拉开声口/底层诉求/反应方式
4. **禁止章节自指**：「这几章」「前面几章」「本章」等元叙述必须消除
5. **Show Don't Tell**：情绪通过行为和反应展示，而非直接描述
6. **信息量零损失**：去味不等于删减，是换一种更「人」的方式表达

### 6.3 钩子技法体系（oh-story，最完整）

**章尾13式**：突然揭秘/紧急危机/未完成动作/身份反转/选择困境/情感转折/信息缺口/对话悬念/时间跳跃/危机升级/系统激活/截断/悬疑预感

**章首7式**：悬念对话/闪前片段/倒计时/反常物件/感官冲击/身份伪装/承接异变

**段落级10式**：信息缺口/倒计时/反转/暗牌/打脸/代价/脆弱/幽灵视角/反常物件/假顺从

### 7.2 各项目的核心优势

- **oh-story**：方法论深度最强（outline-arrangement 2590行，hook-techniques 862行），扫榜能力独有
- **Lorn**：工程化程度最高（50+ Skill + 脚本门禁 + 5段4门禁 + 竞对驱动），去AI味体系最完整（13个 reference）
- **long-novel-writer**：百万字级状态管理最清晰（8文件记忆层 + 多级更新策略）
- **inovel**：桌面体验最好（富文本 + 世界观图谱 + 版本控制）
- **novel-hub**：数据架构最优雅（File-as-Truth 原则）
- **AINovel**：批量生成效率最高（并发控制 + 多账户轮换）

### 7.3 各项目的不足

- **oh-story**：无自动化门禁脚本，无多平台输出，无桌面UI
- **Lorn**：无编程化后端（纯 Markdown + PS 脚本），无数据库持久化
- **long-novel-writer**：无去AI味体系，无质量评分，提示词需从原项目蒸馏
- **inovel**：无 AI 写作能力集成，无去AI味，无质量审计
- **novel-hub**：无 AI 写作流程，功能开关依赖前端
- **AINovel**：无质量控制，无去AI味，无世界观管理，纯生成器
